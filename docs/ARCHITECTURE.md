# Архитектура Deskline

Самостоятельный проект портфолио на Python. aiogram принимает команды Telegram, FastAPI обслуживает административный REST API, JavaScript показывает расписание. Оба процесса используют один SQLite-файл через общий Docker volume. По умолчанию запускается только панель; polling бота включается отдельным профилем.

Услуга задаёт продолжительность и цену в копейках. Slot — конкретный момент начала в UTC; в этой версии один бизнес обслуживает одного клиента одновременно, поэтому starts_at уникален глобально. Booking связывает Telegram user ID с временем. Подтверждённые и завершённые записи занимают слот; отменённые освобождают его.

BEGIN IMMEDIATE сериализует проверку повторного update_id и вставку записи. Частичный уникальный индекс на slot_id для активных статусов защищает от двойного бронирования на уровне БД. processed_updates связывает Telegram update_id с результатом: повтор обработки возвращает ту же запись. База и запись повтора меняются в одной транзакции.

Telegram user ID берётся из объекта Update, не из текста команды. /mine и /cancel ограничены этим владельцем. Администратор входит отдельно через cookie-сессию; пароль хранится как scrypt, токен — хеш. Публичной регистрации администратора нет.

Синхронная SQLite-работа обработчиков выполняется через asyncio.to_thread, чтобы не блокировать event loop aiogram. FastAPI sync endpoints выполняются в worker threads. У каждого запроса своё соединение. При нескольких серверах или большом числе записей нужны PostgreSQL, миграции, ограничение нагрузки и общий limiter.

Тест aiogram использует настоящий Dispatcher.feed_update с подставным BaseSession: исходящие SendMessage перехватываются, сеть не вызывается. Это проверяет маршрутизацию и ответы, но не доступность Telegram, токен, polling и реальную доставку. Такой live smoke не выполнен без пользовательского BOT_TOKEN в локальном окружении.

Обновление интервалов: один ресурс бизнеса, занятость [start, start + duration). Проверка внутри BEGIN IMMEDIATE запрещает пересечения между разными слотами и услугами, учитывает смещения часовых поясов. Соседние интервалы допустимы; cancelled освобождает время, completed продолжает занимать исторический интервал. Тесты охватывают частичное пересечение, вложение, обратное пересечение, одинаковое время с разными UTC-offset, смежность и отмену. Интервалы не привязаны к нескольким сотрудникам; реальная Telegram-доставка по-прежнему не проверена.
